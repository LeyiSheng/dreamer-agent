# 冻结 Dreamerv4-MC 智能体与分层增强计划 v6

日期：2026-09-12。状态：实施主准则；不是实验成功声明。

本文件完整继承 [v5 原文](PLAN_V5_SOURCE.md) 的 P0—P4、模块范围与实验矩阵；以下修订优先于 v5。旧 INTEGRATION_PLAN、Route A 及根目录旧优化稿仅供历史诊断，不能改变本计划。实验是第二准则，可否定假设，不允许以旧代码行为重新定义成功。

## 1. 范围与阶段

目标是冻结公开模型上的方法构建，不称原版完整复现。不承诺铁镐/钻石目标成功率或固定总工期。P0/P1 为首批工程；P2 的短任务真实增益决定是否开展 P3；P4 为可选研究，不按日历自动解锁。

|阶段|必须提供的证据|失败处理|
|---|---|---|
|P0|固定权重/代码/动作规格；真实历史条件推演；分支状态隔离；实测吞吐及显存；采集、消耗、合成和跨时间库存语义测试|缺权重则报告缺失；语义失真则缩小任务，不进入长程 RL|
|P1|按原始会话隔离数据；像素历史策略 BC；事件奖励的独立校准；真实短任务基线|优先修复数据、动作和表征，不由搜索替代低层能力|
|P2|短 rollout 16→32→64；固定 BC prior；多训练种子的真实增益|模型内提升无真实提升时诊断，不解锁分层|
|P3|固定低层比较手写与自主调度；高层全局奖励；逐项风险消融|分清技能交接失败与高层选择失败|
|P4|等模型调用预算下搜索优于简单 rollout 教师；蒸馏学生有真实收益|搜索教师无增益则停止，不做无效蒸馏|

## 2. 数据与表征

数据记录必须有原始 source_episode_id、片段 episode_id、split、来源种类。来自同一原始会话的多个切片必须归于同一 split；近重复视频需额外检查，不能声称分组即可排除全部泄漏。合成 demo 只能用于测试。真实评估轨迹不得进入训练、搜索根或奖励标注。

初版路径：冻结 Tokenizer → 可训练因果时序网络 → 先无任务基础BC，再用事件标签训练任务条件策略。随后冻结对应表征，训练/校准奖励；P2 不变更该表征。第14节为当前执行顺序。动作历史和像素推断的库存信念始终采用相同接口。真实事件仅作监督，不作为信念输入。

MTP 为 8 个预测目标；初版仅执行当前动作，每步重新观察。未来预测头不等于开环执行 8 帧。动作合法支持集必须由经过验证的动作协议提供，不硬编码旧仓库的 12×68 假设。

## 3. 奖励与终止

低层奖励用于当前技能的可观测完成；高层初版使用全局首次里程碑奖励，episode 内不因技能切换清空。重复采集数量奖励须另行定义、消融；不允许重置完成记忆刷分。

奖励校准报告每技能精确率/召回率、误报数、样本数、置信区间和高分尾部错误；阈值在独立校准集确定。连续确认只能降低短暂误报，不能证明幻觉正确。

技能结束不等于环境终止。只有真实任务终止取消自举。timeout 保留边界自举但不能跨 episode 递推；uncertainty_cut 丢弃不可信转移，保留有效前缀，边界使用有限上下界内的停止梯度值，单独记录截断。该规则不保证无偏或悲观。

宏观奖励按 gamma^j 聚合，折扣 gamma^duration；高层优化全局进展，不累加可重复低层完成分数。经验离线回报阈值不得称数学价值上界。

## 4. 模型、风险与搜索

P0 需检查材料消耗、物品持久性、关闭/重开背包和完整短技能时长。外部库存记忆不能修复内部动力学遗忘。动作敏感性与反事实准确性分别报告。

世界模型状态包含 latent/action 历史、cache、位置和随机状态；克隆由适配器负责并通过真实实现测试，不能把 Python deepcopy 作为 GPU cache 正确性的证明。

多样本分歧只能作为风险代理；先软可行性和短 rollout，再单独加截断与价值约束。搜索记录每技能多个随机后继、持续时间和总模型调用量。先比较无搜索、简单候选 rollout、MCTS，再蒸馏。搜索教师不是能力上界。

## 5. 评估与证据

默认严格离线：真实评估不用于调参、挑选 checkpoint 或反馈标注；阶段继续/停止按预注册规则执行。若要用真实开发集自适应调优，必须在实验协议中明确改变这一设置，并保留独立最终测试集。

固定世界种子、动作频率、起始状态、任务时限、环境版本、checkpoint、训练种子。失败到达时间报告删失。至少 3 个训练种子分别报告；稀有事件 1000 episodes 是预算候选，正式运行前明确每种子还是合计。统计协议冻结后才启动正式评估。

H0/H1 固定低层，B1/H1 比较使用相同低层版本。S1 必须有等总算力无搜索基线。实验先报告原始成功次数与区间，再报告百分比。

## 6. 当前首批交付与限制

新建独立 `dreamer_agent` 主线：数据来源/切分约束、里程碑去重、持续时间 return、带动作支持集的历史条件 MTP 策略、PMPO 与离线 BC 损失、P0 资产审计命令。以手算目标和梯度测试验证核心；不导入旧 mc_hier。

后续尚需：真实 VPT 格式导入、动作往返验证、Tokenizer/动力学适配器、奖励训练校准、完整 BC 数据训练入口、真实 Minecraft 评分器。没有这些证据不能宣称 P0/P1 完成，更不能启动 P2。

## 7. 远端 P0/P1 实施细化（2026-09-12）

默认工作目录为 <SSH_HOST>:<PROJECT_ROOT>。实现与证据以远端版本为准。

- P0 动作规格从安装的 tokenizer 做兼容性验证，独立策略使用局部类别 ID，经严格支持集映射至 WM token；不把兼容性测试称为真实动作语义验证。frame_hz/action_repeat 为显式声明，仍需环境验证。
- VPT 先审计原始 JSONL 必需字段和连续 tick，再核对视频。T 个动作与 T+1 帧是待确认的观测对齐情形，不自动裁剪。当前样本 6000 动作/6001 帧，因果偏移尚未确认。
- P1 已提供新的 NPZ + manifest 监督训练入口，要求原始会话分组、文件哈希、冻结视觉提取器及预处理哈希；不读取旧 PT 缓存。第一版内存加载，仅用于小规模数据验证。
- 导出格式限定 features/actions/tasks/frames。字段约束不能证明 features 数值确实来自像素；正式训练仍需提取器与原始视频的可追溯导出审计。
- MTP 标签在任意中途任务切换处停止；片段尾部使用右侧 padding，GRU 输入不混入其他 episode。训练窗口从零隐状态启动，部署历史长度与缓存策略仍需验证。
- reward calibration 中 Wilson 区间假设独立观测，只作为诊断；阈值选择后必须独立确认，并处理同 episode 相关样本。不能仅凭该函数的 passed 字段开启 RL。
- 这些代码不代表 P0/P1 验收完成。下一步：官方权重 revision/内容核验，真实上下文推演及 cache 隔离，动作观察偏移确认，新特征导出，真实事件监督与奖励头训练，真实 BC 子任务评估。

## 8. 预填充适配修复（2026-09-13）

当前推理主线改用 dreamer_agent/world_model.py 的 FrozenWorldAdapter，不调用旧 MCWorldModelInfer/prefill 包装器。Tokenizer/Dynamics 与已审计的底层采样原语是待验证推理后端，不作为训练算法正确性的依据；本轮未改变采样公式或冻结权重。

适配器明确仅支持 batch=1 的串行执行：reset(pixels, frame_actions, seed) 返回最后潜变量；step(action) 返回潜变量与解码图像；clone_state/restore_state 保存或恢复显式 CPU 缓存快照。暂不提供多个调用者共享同一 backend 的并发保证；一个 backend 应只属于一个适配器。快照带实例标识，禁止跨实例恢复。

frame_actions 必须由调用者提供已对齐的逐观测动作，不自动推断或裁剪 VPT 的 T+1 帧。输入时间步与动作逐帧一一匹配；Tokenizer 按时间维解码，图像/动作形状与合法支持集在更新缓存前检查。预填充噪声与生成噪声统一由实例 Generator 提供，重置清空缓存与历史。生成失败使实例失效，必须 reset 或恢复有效快照。

缓存内容 k/v、计数、索引、Generator 状态、有限潜变量及动作历史纳入快照；位置旋转表对固定图像尺寸初始化后只读。本轮真实模型测试涵盖短分支恢复与34步生成，不等于长时所有缓存行为已验证。

验收进展：两帧与四帧真实上下文预填充、34步有限输出、重置/分支精确重放通过；模型任务语义、真实时间对齐、损坏视频恢复、奖励校准与BC基线仍未通过。因此P0不作整体完成声明，P2不解锁。

## 9. 长窗口回归与数据导出门槛（2026-09-13）

适配器强制一个活跃 backend 仅属于一个适配器，拒绝共享可变缓存。真实冻结权重完成 4 帧上下文后 264 步生成，跨越 256 帧 dynamics 窗口；窗口边界分支恢复、reset 重放及实例 RNG 隔离通过。该结果只扩大了接口与确定性验证范围，不证明长期物品持久性或任务成功。

新增 sources.py：按原始会话标识（不含片段日期/时间）提出固定 seed=20260913 的 train/calibration/test 分组；筛查 116 个源，1 个损坏容器拒绝，其余 115 个仍为 alignment_pending。分组目前是候选协议，需近重复审计和 split 用途确认后冻结。容器可读不等于全片完整解码或动作记录语义有效。导出校验 require_export_ready 要求外部对齐证据及内容哈希；后续导出器必须调用此门槛。当前尚无已批准真实特征导出，禁止把筛查记录直接作为训练 manifest。

新增 alignment_diagnostic.py，以固定首 600 帧和共同有效样本集比较 -3 至 +3 的画面位移/鼠标动作相关性。三个不同会话分别偏向 0、+3、-1，后两者相关性较弱，不能认证统一偏移，亦不能证明不同会话真的具有不同偏移。该工具始终输出 alignment_verified=false，不自动裁剪、重标注或批准训练。

下一项必需证据：在明确属于离线开发用途的源中，固定样本与判据，核对可辨识的孤立转向/GUI 开闭事件及原始录制时间语义；报告歧义和失败，不以最大相关性选偏移。完成逐源对齐和完整解码后再构建带哈希的冻结 Tokenizer 导出。不得因本轮技术回归通过而解锁 P2；奖励校准与真实 BC 评估仍缺失。

## 10. 官方 VPT 配对协议复核（2026-09-14，修订第9节）

根据用户指定的 OpenAI Video-Pre-Training 官方仓库，data_loader.py 对每一行 JSONL 顺序读取一帧，配对 frame[i] 与 action[i]；跳过空动作发生在读取帧之后。因此对于完整可读且来源符合该格式的 T+1 帧/T 动作文件，BC 使用前 T 个同序号配对，剩余尾帧不作有标签 BC 样本，原文件保留。不能仅凭多一帧认定错位，也不能将相关性最大值作为重新对齐依据。

修订第9节的硬门槛：运动相关性诊断降为异常提示，不再要求其一致才能采用官方同序号 BC 协议。正式导出仍需逐源来源/格式、完整解码、动作转换及可追溯哈希审核；registry 旧记录不自动改为 approved。应将“遵循已审核配对协议”与“实验测得物理因果偏移”分开记录，不能混用 alignment_verified 含义。

官方 BC 配对规则不直接证明 Dreamerv4 动力学预填充 action[i] 是进入还是离开 latent[i] 的动作，该后端约定需要单独核对。官方示例跳过空动作，不能直接用于本项目固定20Hz序列压缩；本项目保留时间轴，必要时单独调整损失mask。VPT的128×128预处理也不能替代冻结世界模型的输入协议。

公开 behavioural_cloning.py 是单步负对数似然微调示例，维护分轨迹隐状态但每步detach，不是论文完整训练实现。只采用其数据协议证据，不复制示例训练器。源版本、文件哈希及快照见 outputs/vpt_protocol_20260914/。

## 11. 权重 head 前置核查（2026-09-14）

用户要求先确认 reward head/policy head。当前实际使用的 IamCreateAI/Dreamerv4-MC 固定快照 a2e3bb67f3d5c012fa33ba81153eb42e0341fc69 中，两份权重仅为 Tokenizer 与动作条件 Dynamics；均不含 reward head 或 policy head。Dynamics 的 head 输出32维图像latent，action_embedding/action_in是输入条件而非策略；Tokenizer decoder head输出RGB图像patch。核查依据为完整safetensors键/形状、配置、forward输出及此前严格加载记录，报告 outputs/head_audit_20260914/report.json。

当前权重作为冻结世界模型使用，不视为已有策略/奖励的完整智能体。原始计划第5节已明确自行训练策略、奖励头和完成检测器；用户于2026-09-14再次确认此路线。缺少预训练policy/reward head是既定实施前提，不是P1阻塞条件，也不要求另找权重或再次确认。继续按第2节顺序：冻结Tokenizer与Dynamics，基于离线动作监督训练因果时序网络与任务条件BC策略，再冻结表征，训练并独立校准奖励头与完成检测器。价值网络在P2阶段训练；P2仍须满足世界模型能力、奖励校准及真实BC基线门槛。此前新增的全面暂停条件撤销。新主线已有策略代码不代表训练完成，既有推理回归也不代表任务成功。

## 12. P1自训组件实施（2026-09-14）

新增 dreamer_agent/reward.py：RewardCompletionHeads 以冻结BC历史 h_t、后继历史 h_{t+1} 及任务ID预测事件和完成两类logit。事件和完成分别监督，二者不替代环境terminated。主线保持稀疏事件奖励，不新增塑形。输入历史强制detach；frozen_history要求BC整体eval且参数冻结，避免奖励学习改变表征。HistoryPolicy显式提供任务无关encode_history，原策略输出计算保持一致。未知标签使用独立mask，不当负例。

该模块实现可学习的head与监督损失，尚非已训练奖励权重，也尚非完整数据训练入口。正式训练须先产出可追溯视觉导出、训练BC并冻结版本，再建立带来源与逐技能正负例的事件/完成标签。之后接入独立校准；sigmoid概率不得直接视为可靠奖励，连续确认和里程碑去重仍由执行层负责。

## 14. 第一阶段基础BC与后续任务训练解耦（2026-09-14，当前执行顺序）

依据VPT官方BC加载/训练代码，以及Dreamer 4论文第3.3、4.1节，明确三类监督：
- 基础BC（P1a）：只需视频与动作，不需技能ID、奖励标签或完成检测器。
- 任务条件BC（P1b）：从VPT已有离线事件构建任务相关片段与任务标签；优先检查原始事件覆盖，缺失/歧义才补注或缩小任务。不得仅生成空模板后停工，也不得根据最终事件强行标注整段目标。
- 奖励训练（P1c）：用已有事件构建稀疏奖励及负例，冻结对应表征后训练/校准。正负例门槛只约束奖励训练，不阻塞基础BC。独立完成检测器是本项目设计，不是VPT基础BC要求。

上述顺序覆盖第11—13节所有“必须先有技能/奖励标注才能导出或训练”的笼统描述。原任务条件导出入口保留，用于P1b/P1c；新增无任务数据模式用于P1a。该模式禁用任务embedding，tasks数组的固定0仅为统一张量接口占位，不表示伪造技能，不产生reward_labels。基础BC独立入口不得自动调用奖励训练。

原文对照：VPT基础模型采用无任务动作模仿；Dreamer 4利用VPT已有事件构建任务及稀疏奖励，智能体微调时联合动作/奖励/视频预测损失。其50%均匀、50%任务相关序列设置属于多任务联合训练阶段，不强行用于本项目未筛选技能的基础BC。我们冻结Tokenizer/Dynamics、外挂GRU与二元事件/完成头是明确工程改造，不称原文完全复现。
